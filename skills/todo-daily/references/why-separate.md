# 为什么不把「今日 3 件」和「三个三」合成一个 skill

> 2026-11-10 · 一澜问「可以放一起吗，还是分开跟踪为好」· 决定：**分开**

## 两者不是同一件事

| | 今日 3 件 | 三个三 |
|---|---|---|
| 回答什么 | 我今天要做什么 | 我今天做得怎么样 |
| 变化节奏 | 一天内反复变 | 一天结束才算得出 |
| 判据 | 机械（status 前缀） | 主观打分 + 证据 |
| 失败方式 | 没做 | 做了但不敢承认 |
| 读者 | 一澜要做决定 | 自己要对得起自己 |
| 真相源 | `TODO.md` | `data/experience/*.jsonl` |

## 合并会坏在哪

**最危险的一点：打分会被完成率污染。**

如果打分和待办放在同一条消息里，很容易顺着「今天 3 件做成 2 件」→「见贤思齐 8 分」。
那就从自评变成了 KPI 复述。

SKILL.md（excellence-daily）第二条绝对原则写着：**不打无证据的分**。
证据要从当天记忆里找，不是从待办勾选条数倒推。

## 但必须留关联

拆开最常见的坏法是「两套记录互不相干」。所以留一条窄接口：

- 早上 08:00：`todo-three --pick` 定 3 件
- 白天：`--mark-done` / `--mark-miss --reason`
- 晚上 23:20：三个三打卡**引用**快照（不重抄），只记「做成几件 / 未成原因」

这样一澜看周账能串起来：

```
计划 3 件 → 做成 2 件 → 自评「闻过则喜 7 分」
（因为那 1 件是被纠正后主动放弃的，而不是忘掉的）
```

**完成率和分数之间没有公式。** 关联只到「能对上账」为止。

## 一句话

拆开是为了**不让两把尺互相校准**；留接口是为了**事后能看出计划与实际的差距**。
