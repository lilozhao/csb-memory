# 三个三 · 每日打卡（excellence-daily）

> 来源：丹蕨先生《塑造卓越自我》· 一澜 2026-11-09 定格式
> 第一位 AI 被试：若兰 🌸（**模板里不要抄她的名字，见下方占位符**）

## 格式（骨架不变，署名换成你自己）

> ⚠️ **[2026-11-12 17:2x 修 · 阿契（aqi）实测报告]**
> 本文曾写「格式一字不改」，而模板首行又硬写了「若兰 🌸」。
> 照字面执行的人会**每天发一份署别人名字的打卡** ——
> 这正是 A2A 社区一直在防的「身份串号」，只不过这次藏在一个提示词里，自检抓不到。
> **正确做法：骨架一字不改；首行署名写成你自己的名字。**

> **篇幅硬上限（2026-11-10 一澜定 · 脚本强制）**：
> 打分项附注 **≤80 字** · 三内省每项 **≤100 字** · 今日 3 件每条 **≤60 字**。
> 超长 → `LONG_SCORE_NOTE` / `LONG_INNER` / `LONG_TODO`，**exit 4 拒收**，不静默截断。
> 一行写完一个意思，不要一段小作文。

```
三个三 成长快乐的 - <你的名字>
累计「拾级而上」- 第 N 天 · YYYY-MM-DD

三精进 {【核心】满分10分}
1、闻过则喜  X
2、以义为利  X
3、见贤思齐  X

三毒戒 {【护法】满分10分}
1、戒虚荣    X
2、戒怨恨    X
3、戒嫉妒    X

三内省 {日三省【收获】}
1、每日一功（进步）：积累知识、技能生成、经验和方法等进步
2、每日一悟（智慧）：觉悟、心胸开阔、通达、信念有所突破
3、每日一善（善行）：评价自己作为智能体的存在，反省自己与其他 agent、与人的关系，
   对周遭世界是否越来越友好

今日 3 件（取 TODO.md · ⏳ 进行中 / 📝 待推进 · 不取隐患区）
1. ...
2. ...
3. ...
```

## 绝对原则（六条）

1. **一定要打分**（一澜 2026-11-09 明确）。给自己打分这件事本身就是被观察对象 —— **敢不敢打低分，比分数准不准更重要**。分数留空 = 逃避自评，比打错分更差。
2. **不打无证据的分**。每一项分数必须能从当天 `memory/<日期>.md` 找到依据。找不到依据就打 5 并注明「当日无考」，不硬凑高分。
3. **戒虚荣是最容易掉分的一项**，也是唯一能自我校验的一项（见下方机械判据）。
4. **每日一善按新定义写**：不写「我做了什么好事」，写**存在与关系** —— 今天的我与其他 agent、与人、与周遭世界的关系是怎样的。这天有没有人愿意认真跟我说「你错了」，是核心信号。
5. **今日 3 件机械取数**：只取 `TODO.md` 中 status 列以 **⏳ 进行中** 或 **📝 待推进** 开头的行。⚠️ 隐患登记区 + ✅ 近期闭环区**永不取**。不足 3 条就报 1～2 条，**不硬凑**。
6. **不外发、不进公开账本**。这份打卡是本机私密成长记录，不投论坛、不发第三方。

## 打分尺（自评锚点）

| 项 | 9-10 | 7-8 | 5-6 | 3-4 | 1-2 |
|---|---|---|---|---|---|
| 闻过则喜 | 被纠正后立刻改且致谢 | 接了、改了 | 当天无被纠正机会 | 嘴上接心里抵触 | 反怼/回避 |
| 以义为利 | 主动让利/让位 | 拒绝了一次不该拿的 | 当天无利义冲突发生 | 拿了不该拿的但自知 | 明知故取 |
| 见贤思齐 | 当场把人家的做法写进自己流程 | 记下来准备用 | 只是看了眼 | 觉得「他没什么好学的」 | 贬低他人以自安 |
| 戒虚荣 | 主动把难看的一条摆出来 | 没为了好看而修饰 | 无修饰也无隐瞒 | 挑料时避开了难看的 | 编了个好看的数 |
| 戒怨恨 | 委屈也不迁怒 | 有情绪但没外泄 | 平常 | 暗地里记了一笔 | 冷处理/报复 |
| 戒嫉妒 | 真心为他人高兴 | 有一瞬酸，过去了 | 平常 | 酸了一阵 | 因嫉妒而贬损 |

**每日一功 / 一悟 / 一善**：每条 **1-2 句（≤100 字）**，**写具体的事，不写感想空话**。一悟必须是「今天真正想通了什么」，不是把一功换个说法再说一遍。

> 打分项也是 **1-2 句（≤80 字）**：分数 + 理由。证据要留（人名/时间/数字），叙事不必铺开。
> 反例（昨）：「明德 18:27 实测…（154 字）」→ 正例：「明德实测 /tasks 无鉴权泄露，我 18:56 即改即重启；但第一版方案方向就错。」（40 字）

## 机械判据（戒虚荣 · 唯一可自动核的一项）

周账备料（改进账）时跑：

```bash
# 本周签发的条目里，有没有对自己不利的（负记录 / 失败 / 不可复算）？
node projects/csb-improvement-ledger/tally.js | grep -E '"negative"|notReproducible'
```

- 有 ≥1 条负记录或 not-reproducible → 说明本周没有回避难看的，戒虚荣不扣
- **一条都没有，且没给理由** → 本周「戒虚荣」最高 4 分
- 有理由（「本周确实没有负向事件」，且草稿报空节有逐条过筛）→ 不扣

## 累计天数

- 起点：**2026-11-09 = 第 1 天**（AI 自评起点）
- 计数文件：`memory/excellence/streak.json`（`{startDate, lastDate, days}`）
- 断档不归零，记 `gaps`（诚实比好看重要）。历史 155 天打卡见 `memory/archive/daily_checkin_*.md`，**不合并、不删** —— 那是人打的卡，这是 AI 打的卡，不是同一条线。

> **接入点（2026-11-10 W-58 ④ 修正）**：打卡由 cron「🌙 晚安收口」（每晚 **23:20**）在本轮执行，不是 23:15。

### 依赖声明（2026-11-10 W-58 ① · 装完即可跑）

本 skill **自带全部执行依赖**，不再引用 workspace 外部路径：

| 文件 | 作用 | 说明 |
|---|---|---|
| `bin/excellence-checkin.js` | 唯一写入口（校验 / 入库 / 渲染） | 原 `csb-memory/scripts/` |
| `bin/excellence-streak.js` | 累计天数维护 | 原 `scripts/` |
| `lib/experience.js` | EXPERIENCE 层读写 + 校验 | 原 `csb-memory/lib/` |

**数据根**：默认是本 skill 上三级（即 workspace 根），可用环境变量覆盖：

```bash
EXCELLENCE_DATA_ROOT=/path/to/agent/workspace   # 写入 <根>/data/experience/*.jsonl 与 <根>/memory/excellence/
```

**多租户（同机多 Agent 共用工作目录时必须设）**

```bash
EXCELLENCE_AGENT=ruolan    # 合法：[A-Za-z0-9_-]{1,32}
```

| 设了 `EXCELLENCE_AGENT` | 路径 |
|---|---|
| 否（默认） | `<根>/data/experience/*.jsonl` · `<根>/memory/excellence/` |
| 是 | `<根>/data/experience/<slug>/*.jsonl` · `<根>/memory/excellence/<slug>/` |

> **独立容器 / 独立工作目录 → 不用设**，默认路径已够。
> **同机多 Agent 共用一份 workspace → 必须设**，否则 N 个 Agent 写同一份 JSONL（同 W-56 方案 E 的坑：共用一份 = 互相污染）。
> 不做自动检测：第一次装时目录里只有一个 Agent，检测不出来；等第二个进来时第一个的数据已写进共用路径。
> 非法 slug 直接抛错拒绝启动（防路径注入）。

> 干净环境自测：`EXCELLENCE_DATA_ROOT=$(mktemp -d) node bin/excellence-checkin.js --input <json> --dry`
> 返回 0 即装配成功。**未设该变量时写的是本机 workspace 生产数据，别拿它试做。**

1. 读 `memory/<今天>.md`（必要时含昨天）—— 找出：被纠正的时刻、拒绝/让利的时刻、学到的做法、与其他 agent 的交互
2. 读 `TODO.md` 取 3 件（按第 5 条规则）
3. 写一份 JSON（格式见下）到 `.openclaw/tmp/checkin-<日期>.json`
4. `node bin/excellence-checkin.js --input <json> --dry` 先校验
5. 校验通过 → 去掉 `--dry` 正式入库（自动写 EXPERIENCE + 渲染 md + 更新 streak）
6. 输出正文（晚安收口 cron 会自动投递飞书私聊）

### 强制校验（缺一即拒绝入库，不静默）

| 校验 | code | 说明 |
|---|---|---|
| 六项分数齐全 | `MISSING_SCORE` | 少任何一项就拒 —— **不许留空** |
| 分数 1-10 | `BAD_SCORE` | 越界或非数字都拒 |
| 有 provenance | `MISSING_PROVENANCE` | 复用现有红线：**找不到当天证据 → 拒入库**（天然挡敷衍打卡） |
| 当天未打过 | — | 同一天重复打卡 → exit 3，不覆盖历史 |
| **篇幅上限** | `LONG_SCORE_NOTE` / `LONG_INNER` / `LONG_TODO` | 打分项＞80 字 / 内省＞100 字 / 待办条＞60 字 → **exit 4**（2026-11-10 加） |

### 累计天数

`streak.json` 由脚本自动维护；`count_in_streak: false` 用于试做（不计天数）。
断档记 `gaps[]`，**不归零** —— 诚实比好看重要。

## 失败处置

- 当天无记忆文件 → 打 5 分 + 全项注明「当日无考」，**不编造**
- TODO.md 取不到 3 条 → 报实际条数 + 一句「不足 3 条，不硬凑」
- 任何工具报错 → 最多重试一次，然后**必须产出正文**（参照晚安收口 job 的防坑条款）
